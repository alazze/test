Qualité des données

    Comment lire les taux

    ¹ Confirmation = confirmées / commandes dont le statut de confirmation est connu. ² Livraison = livrées / expédiées dont le statut de livraison est connu. Si la couverture est partielle, les taux portent uniquement sur les commandes renseignées et peuvent être biaisés. Les commandes récentes n’ont pas encore toutes un résultat final.

    Les filtres utilisent la date de création Shopify, dans le fuseau indiqué par l’export. L’ancienneté est calculée par rapport à la fin de période choisie. Les taux par produit portent sur les commandes contenant ce produit : une commande avec plusieurs produits apparaît dans plusieurs lignes.

    La valeur commandée correspond au Total Shopify, avant soustraction des remboursements. Elle ne représente ni l’argent encaissé ni le bénéfice. Coûts, frais COD, publicité et versements du service seront nécessaires pour calculer la rentabilité réelle.

    Coûts par produit estimés selon les tarifs et la part de valeur articles dans les commandes contenant plusieurs produits. Les frais réels du service sont disponibles au niveau des factures globales.

    Format normalisé du service

    store, shopify_id ou order_name, confirmation_status, shipping_status, delivery_status, updated_at (date ISO avec fuseau). Un store est obligatoire pour éviter de confondre les numéros identiques entre boutiques.

    Confirmation : confirmed, cancelled, pending, unreachable, unknown. Expédition : shipped, not_shipped, unknown. Livraison : delivered, in_transit, refused, returned, failed, pending, unknown. Les lignes non rapprochées sont signalées et ne modifient pas les taux.
